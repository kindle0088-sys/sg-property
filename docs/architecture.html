一、数据管道架构

五层：数据源 → 采集 → 构建 → 产物 → 展示

要点

  • URA 受地域限制，必须本地（新加坡 IP）拉取；HDB 用 data.gov.sg 无地域限制。
  • 构建入口：scripts/build.js，支持 --skip-hdb / --skip-ura / --fresh 三种模式。
  • 产物分类：楼盘明细（data/projects/*.json）、聚合索引（market-summary / property-index）、HDB 系列（hdb-*.json）。
  • 展示出口：GitHub Pages 站点（每日更新）+ reports/ 研报（独立发布到 sg-property 仓库）。

二、每日自动化时序

两条流水线：本地 06:00 URA 构建 · CI 04:00 HDB 增量

本地计划任务（06:00 SGT）

run-daily-build.cmd，由 Windows 任务计划程序触发，5 个步骤串行执行：

  1. 禁 git auto-gc，清除残留 rebase 状态。
  2. fetch → merge --ff-only origin/main（分叉则 reset --mixed）。
  3. node build.js --skip-hdb（仅 URA 数据构建）。
  4. 仅真实变更才 commit → push origin main。
  5. 显式 git gc --quiet，loose objects 超 6700 告警。

GitHub Actions CI（04:00 SGT）

.github/workflows/hdb-refresh.yml，cron: '0 20 * * *' UTC：

  1. 每日 04:00 SGT 触发。
  2. HDB 增量拉取（_id 锚点 + data/hdb_cache 缓存复用）。
  3. node build.js --skip-ura。
  4. 仅 hdb* / property-index 等真实变更才 commit → push。
冲突风险源：两条流水线都向 market-summary.json / property-index.json / hdb-index.json 这三个聚合文件写入。历史教训（2026-08-06）：本地脚本原"先 commit 后 pull --rebase"，冲突残留 → 次日构建在 detached HEAD 上 commit，数据永远推不上去。

对策

先对齐远程再构建。已固化在 run-daily-build.cmd：

  • git fetch origin
  • git merge --ff-only origin/main（落后快进）
  • 分叉则 git reset --mixed origin/main（丢弃本地 commit，数据由本次构建重新生成，reflog 可找回）
  • 之后才执行 build.js

这样 push 必为 fast-forward，不会出现非快进冲突。失败处理：写 logs/build-error.log + 自动开 GitHub issue（去重，避免重复告警）。
